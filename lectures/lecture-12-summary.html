Chapters 1–2 Recap

🔗 Variables Are References — The Copy vs. Alias Trap, One More Time

1A variable is a name bound to an object in memory, not a box holding a value directly. This matters most with mutable objects like lists:

alias_vs_copy.py
my_list = [1, 2, 3, 4, 5]

my_list_save1 = my_list          # ALIAS — same list in memory
my_list_save2 = my_list.copy()   # COPY — a new, independent list

my_list_save1[2] = "2A"   # this ALSO changes my_list!
my_list_save2[2] = "A"    # this only changes the copy
Two other equivalent ways to make a real copy of a list: my_list[:] (a full slice) and list(my_list) both create an independent copy, exactly like .copy(). All three are fair game for exam questions.

🧮 Operators, Casting & Overloading

2The same operator can behave differently depending on the type of its operands — this is called operator overloading.

overloading.py
print(7 + 3)        # 10 — numeric addition
print("7" + "3")    # "73" — string concatenation
print("ha" * 3)     # "hahaha" — string repetition, not multiplication
OperatorBehavior
% (modulus)Remainder after division — the classic even/odd test: n % 2 == 0 means even
// (floor division)Divides and truncates the remainder — it does not round
** (exponentiation)Higher precedence than *, /, +, - — 2 ** 5 is 32
int() truncates, it never rounds. int(9.9) is 9, not 10. Remember also that input() and reading numbers out of a text file always return strings — you must explicitly cast with int() or float() before doing arithmetic.

✅❌ Truthiness and None

3When an if condition isn't an explicit comparison, Python evaluates the expression's truthiness. These values are all "falsy":

  • The number 0 (integer or float)
  • The empty string ""
  • The empty list []
  • None
  • False itself
What causes a function to return None: a function with no return statement at all, or a "naked" return with no value, both implicitly return None. This is different from explicitly returning 0 — 0 is a real (falsy) value, while None means "nothing was returned." Trying to use a None value in arithmetic (e.g., dividing by it) raises a TypeError.

🔁 Loops, range(), break vs. continue

4range(start, stop, step) never includes the stop value. If the step's sign doesn't match the direction from start to stop (e.g., a positive step but a start greater than stop), the loop produces nothing at all — no error, just zero iterations.

break vs. continue in nested loops: break exits only the loop it's directly inside — an inner loop's break doesn't affect the outer loop. continue skips the rest of the current iteration and jumps back to the loop's condition check, without exiting the loop entirely.

🎁 Functions, Tuples & Unpacking

5A function can return multiple values as a tuple. The receiving side "unpacks" that tuple into separate variables — and the order has to match exactly, or you'll silently get the wrong values assigned to the wrong names.

unpacking_bug.py
def order_totals(prices):
    subtotal = sum(prices)
    cheapest = min(prices)
    priciest = max(prices)
    return subtotal, cheapest, priciest   # returned in THIS order

# BUG: this assumes the wrong order
low, high, total = order_totals([12, 45, 20])
# low actually gets subtotal, high gets cheapest, total gets priciest — all wrong!

# CORRECT — must match the return order exactly
total, low, high = order_totals([12, 45, 20])
Tuples are immutable — once created, they can't be changed, unlike lists. This immutability is also part of why Python can apply certain performance optimizations to tuples that it can't apply to lists.

🔤 Strings: Methods, Slicing, Comparison, Formatting

6Strings behave like immutable sequences of characters — similar to a tuple of characters. Every string method returns a new string; it never modifies the original.

string_review.py
s = "Miami Dade College"
s_new = s.lower()      # s is unchanged; s_new is the new lowercase string

fields = "John,Masseria\tMiami,Dade,College".split("\t")
first_last = fields[0].split(",")   # chained: split the result of a split

"date" in "candidate"   # True — checks if a substring appears anywhere
String comparison is case-sensitive and character-code based. Uppercase letters have lower numeric values than lowercase letters, so "Zebra" < "apple" is True (capital Z's code is less than lowercase a's) — but after converting both to the same case, ordinary alphabetical order applies. To compare strings while ignoring case, convert both sides with .lower() first.
F-string formatting recap: f"{value:.1f}" means one digit of precision after the decimal point; {value:.0f}" rounds to a whole number. Remember Python's f-string rounding uses banker's rounding (round-to-even) rather than the "round half up" rule — this won't be tested directly, but it explains why a value like 92.5 can round to 92 rather than 93.

💥 Exceptions Recap

7try/except/finally — code in the finally block always executes, whether or not an exception occurred. This includes exceptions raised inside a function called from within the try block, not just errors on the immediate line.

ExceptionCommon Cause
IndexErrorAccessing a list/string index that's out of range
KeyErrorAccessing a dictionary key that doesn't exist
TypeErrorAn operation between incompatible types (e.g., comparing a string's length directly to a string instead of an integer)
ValueErrorConverting an invalid value, e.g. int("abc")

📋 Lists & Dictionaries Recap

8The sort() vs. sorted() distinction is worth locking in cold: list.sort() sorts in place and returns None; sorted(list) returns a brand-new sorted list and leaves the original untouched.

dict_get.py
scores = {"math": 88, "science": 95}
scores.get("history", 0)   # 0 — no KeyError, since "history" isn't a key
scores["history"]          # KeyError! Direct access raises if the key is missing

dictionary.get(key, default) is the safe way to look up a key that might not exist — it returns your chosen default instead of raising KeyError.

🏗️ Classes & Inheritance Recap

9An attribute declared outside __init__ (no self.) is a class attribute, shared across all instances. Attributes declared with self. inside __init__ are instance attributes, unique to each object.

vehicle_inheritance.py
class Vehicle:
    def __init__(self, make, model):
        self.make = make
        self.model = model

    def display(self):
        print(f"{self.make} {self.model}")

class Car(Vehicle):
    def __init__(self, make, model, doors):
        Vehicle.__init__(self, make, model)   # calls the parent constructor
        self.doors = doors

my_car = Car("Toyota", "Camry", 4)
my_car.display()      # "Toyota Camry" — display() only knows about Vehicle's fields
print(my_car.doors)   # 4 — Car's own attribute
What self really is, under the hood: when Python calls Car("Toyota", "Camry", 4), it allocates memory for the new object first, then passes a pointer to that memory as the first argument (self) to __init__ automatically. Every instance method needs self as its first parameter for exactly this reason — it's how the method knows which specific object's data to operate on.
A required parameter with no default value must always be supplied. If a constructor's first parameter has no default, calling it without a value for that parameter raises an error — a common source of "which of these constructor calls is valid?" exam-style questions.

📦 Modules & Files Recap

10A module is only executed once, no matter how many times (or how many different places) it's imported — Python tracks loaded modules in sys.modules and skips re-running an already-imported module.

File modeBehavior
'r'Read — safe; nothing is erased
'w'Write — erases the existing file the moment it's opened, even before you write anything
'a'Append — adds to the end of the existing file, without erasing it
Closing files matters more for writes than reads. Closing (or using with, which closes automatically) is essential for files you've written to — otherwise your last updates might never actually reach disk. It's good practice for reads too, but the consequences of forgetting are more serious on the write side.

For reading very large files, prefer processing one line at a time (for line in file:) over read() or readlines(), which load the entire file into memory at once — exactly the technique your DNA Sequence Search program should use.
