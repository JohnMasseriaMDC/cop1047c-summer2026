Chapters 1–2

Variables, expressions, and operators

Core facts

  • A variable is a name bound to a value. Names must start with a letter or underscore; use descriptive, meaningful names.
  • Assignment (=) is not equality — it binds a name to a value, evaluated right-to-left.
  • Arithmetic operators: + - * / % ** (exponent) and // (integer division).
price = 19.99
qty = 3
total = price * qty
print(f"Total: {total:.2f}")

print(17 // 5)   # 3  (integer division)
print(17 % 5)    # 2  (remainder)
print(2 ** 5)    # 32 (exponent)

Watch for: operator precedence — ** binds tighter than unary minus in some expressions, and %/// are common exam trick spots. When unsure, add parentheses.

Chapter 4

Branching — if, elif, else

def classify(score):
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 70:
        return "C"
    else:
        return "F"

print(classify(85))   # B
print(classify(65))   # F
  • Conditions are checked top to bottom; the first true branch runs and the rest are skipped — order matters.
  • Comparison operators: == != < > <= >=. Logical operators: and, or, not.
  • Nested conditionals are legal but get hard to trace fast — the final loves a 3-4 level nested if to trace by hand.
  • Truthiness: 0, "", [], None, and False are all falsy; everything else is truthy.
Chapter 5

Loops — while, for, and nesting

nested_loop.py
for row in range(3):
    for col in range(3):
        print(f"({row},{col})", end=" ")
    print()   # newline after each row
(0,0) (0,1) (0,2) (1,0) (1,1) (1,2) (2,0) (2,1) (2,2)
  • while loops when you don't know the count ahead of time (sentinel-controlled); for loops when iterating a known range or sequence.
  • range(start, stop, step) — stop is exclusive. range(5) gives 0,1,2,3,4 — a very common off-by-one trap.
  • Nested loops: the inner loop completes fully for every single pass of the outer loop — trace row-by-row, not all-at-once.
  • break exits the nearest enclosing loop entirely; continue skips to the next iteration.

Trace nested loops on paper. The final will show you a double loop and ask for exact output — write out each outer-loop pass as its own line before you trust your answer.

Chapter 6

Functions — parameters, return values, scope

def compute_area(length, width=1):
    area = length * width
    return area

result = compute_area(5, 3)
print(result)              # 15
print(compute_area(4))     # 4  (width defaults to 1)
  • Parameters without defaults must come first, and are required in the order defined; defaulted parameters are optional.
  • return hands a value back to the caller and immediately exits the function — code after it never runs.
  • A function with no return statement (or a bare return) returns None.
  • Scope: variables created inside a function are local — they don't exist outside it, and they don't persist between calls.
Chapter 6

Returning multiple values — tuple unpacking

order_totals.py
def order_totals(prices):
    subtotal = 0
    cheapest = prices[0]
    priciest = prices[0]
    for price in prices:
        subtotal += price
        if price < cheapest:
            cheapest = price
        if price > priciest:
            priciest = price
    return subtotal, cheapest, priciest

prices = [12, 45, 9, 30]
low, high, total = order_totals(prices)   # WRONG ORDER on purpose - see below
print(f"{low}, {high}, {total}")
  • return a, b, c packages the values into a tuple — (subtotal, cheapest, priciest).
  • Unpacking on the left, x, y, z = func(), assigns by position, not by the original variable names inside the function. The example above deliberately unpacks into low, high, total in the wrong order — walk through it and figure out what actually prints.
  • This exact "which line replaces XXX" / "what does this unpacking print" pattern shows up on the final. The fix is always the same: work out the returned tuple's values in order first, then match them to the assignment targets left-to-right.

Exam strategy: write the returned tuple down as (value1, value2, value3) before looking at the unpacking line at all. Then match position by position — never by guessing which name "sounds right."

Chapter 7

Strings — methods, slicing, immutability

s = "Miami Dade College"
print(s.lower())          # miami dade college
print(s.upper())          # MIAMI DADE COLLEGE
print(s.split())          # ['Miami','Dade','College']
print(s.replace("e", "3"))
print(s[0:5])              # Miami
print(s[-7:])              # College
print(len(s))              # 19
print("Dade" in s)         # True
  • Strings are immutable — every method (.lower(), .replace()) returns a new string; the original is unchanged unless reassigned.
  • Slicing s[start:stop] — stop is exclusive, negative indices count from the end.
  • in tests substring membership and returns a bool.
  • + concatenates; * repeats a string that many times.
Chapter 7

String comparison and formatting

word1 = "Apple"
word2 = "apple"
print(word1 == word2)        # False - case sensitive
print(word1.lower() == word2.lower())   # True
print("Banana" > "Apple")    # True - alphabetical, by character codes
print("apple" > "Apple")     # True - lowercase letters sort AFTER uppercase

name, score = "Sam", 92.5
print(f"{name} scored {score:.1f}%")     # Sam scored 92.5%
  • String comparison (< > ==) is case-sensitive and based on character codes — uppercase letters (A–Z) all sort before lowercase letters (a–z) in standard ASCII/Unicode ordering.
  • f-strings: f"{expr}" evaluates expr inline; format specs like :.2f (2 decimal places) and :>10 (right-align width 10) are exam favorites.

Watch for: "what is output" questions comparing strings with different cases, or comparing a string to itself after a .lower()/.upper() call on only one side.

Chapter 8

Exceptions — try, except, else, finally

try:
    num = int(input("Enter a number: "))
    result = 100 / num
except ValueError:
    print("That wasn't a number.")
except ZeroDivisionError:
    print("Can't divide by zero.")
else:
    print(f"Result: {result}")
finally:
    print("Done trying.")
  • Code in try: runs first; if an exception occurs, Python jumps to the first matching except block and skips the rest of the try.
  • else: runs only if no exception occurred. finally: always runs, exception or not.
  • Multiple except blocks are checked top to bottom — order them most-specific first.
  • Common exception types: ValueError (bad conversion), ZeroDivisionError, IndexError (out-of-range), KeyError (missing dict key), TypeError (wrong type for an operation).

Chapter 9

Lists — mutation, rebinding, aliasing

alias_trap.py
list_a = [1, 2, 3]
list_b = list_a          # ALIAS - same list object!
list_b.append(4)
print(list_a)             # [1, 2, 3, 4] - changed too!

list_c = list_a.copy()    # a NEW, separate list
list_c.append(99)
print(list_a)             # unaffected: [1, 2, 3, 4]
  • list_b = list_a does not copy the list — both names point at the same object. Mutating through either name affects both.
  • .append(), .remove(), .sort(), and index assignment (lst[0] = x) all mutate the existing list in place.
  • list_a = list_a + [x] (or list_a.copy()) creates a new list — the original, if aliased elsewhere, is untouched.
  • This is the exact same reference model that caused the shared-class-attribute bug in Chapter 10 — same concept, different chapter.
Chapter 9

Dictionaries — keys, values, and the sorted-list pattern

roster_scores.py
scores = {}
scores["Ana"] = 88
scores["Ben"] = 95
scores["Cid"] = 71

print(scores.get("Ana"))          # 88
print(scores.get("Drew", 0))      # 0  - default if key missing

all_scores = list(scores.values())    # [88, 95, 71]
sorted_scores = sorted(all_scores)    # [71, 88, 95]
for s in sorted_scores:
    print(s, end=" ")
  • dict[key] = value adds or updates; .get(key, default) looks up safely without raising KeyError.
  • .keys(), .values(), .items() give view objects — wrap in list() to get an actual list you can sort or index.
  • This "convert dict values to a list, then sort it" pattern is a favorite final question — trace it by writing out the unsorted list first, then the sorted result, before predicting the loop's output.

Chapter 10

Classes — the core vocabulary

class Book:
    library_name = "MDC West Campus"     # class attribute - shared

    def __init__(self, title, author, pages=0):
        self.title = title                # instance attributes -
        self.author = author               # unique to each object
        self.pages = pages

    def summary(self):
        return f"{self.title} by {self.author} ({self.pages}p)"

b1 = Book("Fluent Python", "Ramalho", 750)
b2 = Book("Automate the Boring Stuff", "Sweigart")
print(b1.summary())
print(b2.pages)          # 0 - used the default
  • __init__(self, ...) runs automatically at instantiation — self is auto-bound to the new instance; never pass it yourself.
  • Required parameters first, in order; defaults after. Missing the self parameter on any method is the #1 rookie bug: "takes 0 positional arguments but 1 was given".
  • Class attributes (defined in class scope, outside methods) are shared by every instance. Instance attributes (self.x = ...) belong to one object only.
Chapter 10

Instantiation — matching arguments to parameters

class Reservation:
    def __init__(self, guest, party_size=2, notes="none"):
        self.guest = guest
        self.party_size = party_size
        self.notes = notes

# Which of these correctly creates a reservation for "Nguyen",
# party of 4, with no special notes?
r1 = Reservation("Nguyen", 4)
r2 = Reservation(4, "Nguyen")
r3 = Reservation("Nguyen", notes=4)
r4 = Reservation(party_size=4, guest="Nguyen")
  • "Which statement correctly instantiates..." is a guaranteed final-exam question format. The method: identify the constructor's parameter order and defaults, then check each candidate call against it positionally unless it uses keyword syntax (name=value).
  • Above: r1 and r4 are correct (positional and keyword respectively); r2 swaps the types into the wrong slots; r3 puts 4 into notes, not party_size.

Exam strategy: write the constructor's signature down first — __init__(self, guest, party_size=2, notes="none") — then check each answer choice against it one parameter at a time. Don't just "feel out" which one looks right.

Chapter 10

Inheritance — base and derived classes

class Vehicle:
    def __init__(self, make, model):
        self.make = make
        self.model = model
    def display(self):
        print(f"{self.make} {self.model}")

class Car(Vehicle):                 # derived from Vehicle
    def __init__(self, make, model, doors):
        Vehicle.__init__(self, make, model)   # call base constructor
        self.doors = doors

my_car = Car("Toyota", "Camry", 4)
my_car.display()          # inherited from Vehicle
print(my_car.doors)       # 4
  • class Car(Vehicle): inherits every class attribute and method from Vehicle — no copy-pasting.
  • Instance attributes are not automatically inherited — the derived class's __init__ must explicitly call Vehicle.__init__(self, make, model) to set them up.

Chapter 11 · Extra Credit

Modules — organizing code across files

# calc_tools.py
def add(a, b):
    return a + b
def multiply(a, b):
    return a * b

# main.py
import calc_tools
print(calc_tools.add(2, 3))

from calc_tools import multiply
print(multiply(4, 5))     # no prefix needed
  • import module_name — access names with the module_name. prefix.
  • from module_name import name — brings name directly into your namespace, no prefix.
  • A module is only executed once per program run, no matter how many times it's imported — Python caches it in sys.modules.
  • if __name__ == "__main__": guards code so it runs only when the file is executed directly, not when imported.
Chapter 12

Reading text files

with open("roster.txt", "r") as infile:
    for line in infile:
        print(line.strip())      # .strip() removes the trailing newline

with open("roster.txt", "r") as infile:
    all_lines = infile.readlines()   # list of strings, one per line

with open("roster.txt", "r") as infile:
    contents = infile.read()          # one big string, whole file
  • with open(...) as f: is preferred — it automatically closes the file when the block ends, even if an error occurs.
  • Iterating a file object directly (for line in infile:) gives one line at a time, including the trailing \n — .strip() removes it.
  • .readlines() returns a list of every line; .read() returns the entire file as one string.
Chapter 12

Writing text files

with open("output.txt", "w") as outfile:
    outfile.write("First line\n")
    outfile.write("Second line\n")

with open("output.txt", "a") as outfile:
    outfile.write("Appended line\n")     # "a" adds to the end
ModeMeaning
"r"Read (default) — file must already exist
"w"Write — creates the file, or erases existing contents
"a"Append — adds to the end without erasing

Classic exam trap: opening a file in "w" mode when you meant "a" silently wipes out everything already in the file — no error, no warning.

Quick Check

Modules & files — predict first

1) True or false: importing the same module three times in one program executes its top-level code three times.

False. Python caches loaded modules in sys.modules — subsequent imports reuse the cached module without re-executing it.

2) What happens if "data.txt" already has content and you run open("data.txt", "w")?

The existing content is erased — "w" mode truncates the file immediately upon opening.
